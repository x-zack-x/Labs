# Lab Name — WebStrike

**Platform:** CyberDefenders  
**Category:** Network Forensics  

---

## Scenario
A suspicious file was identified on a company web server, raising alarms within the intranet. The Development team flagged the anomaly, suspecting potential malicious activity. To address the issue, the network team captured critical network traffic and prepared a PCAP file for review.
Your task is to analyze the provided PCAP file to uncover how the file appeared and determine the extent of any unauthorized activity.

## Walkthrough

### Q1 — Identifying the geographical origin of the attack facilitates the implementation of geo-blocking measures and the analysis of threat intelligence. From which city did the attack originate?

**What I did:** I opened the PCAP file in Wireshark. This file contains the complete network traffic and the attacker's timeline.
**What I found:** In a typical attack, the attacker initiates the first SYN packet. Their IP address is **117.11.88.124**. By searching this on iplocation.net, I determined the exact location.
**Answer:** Tianjin

---

### Q2 — Knowing the attacker's User-Agent assists in creating robust filtering rules. What's the attacker's Full User-Agent?

**What I did:** The User-Agent identifies the browser used by the machine. I filtered the traffic using the **http** filter to isolate HTTP requests and locate the User-Agent field.
**What I found:** I inspected an HTTP packet and analyzed the application layer. The HTTP protocol headers contained the User-Agent string.
**Answer:** Mozilla/5.0 (X11; Linux x86_64; rv:109.0) Gecko/20100101 Firefox/115.0

---

### Q3 — We need to determine if any vulnerabilities were exploited. What is the name of the malicious web shell that was successfully uploaded?

**What I did:** If the attacker gained access, they likely used a malicious upload via a POST method. I filtered the traffic with `http.request.method == "POST"` to isolate these requests.
  ![wireshark](screenshots/2.jpeg)

**What I found:** I found POST requests from the attacker. Using **Follow TCP Stream** to reconstruct the exchange, I discovered a PHP reverse shell script inside a file named **image.jpg.php**. The double extension was likely used to trick the system or users.
**Answer:** image.jpg.php
 ![wireshark](screenshots/3.jpeg)

---

### Q4 — Identifying the directory where uploaded files are stored is crucial for locating the vulnerable page and removing any malicious files. Which directory is used by the website to store the uploaded files?

**What I did:** After the upload, the attacker must execute the file via a GET request. I used the Wireshark filter: `http.request.method == "GET" && http.request.uri contains "image.jpg.php"`.
**What I found:** The request appeared, revealing the full directory path where the malicious file was stored on the server.
**Answer:** /reviews/uploads/
 ![wireshark](screenshots/4.jpeg)
 ![wireshark](screenshots/5.jpeg)

---

### Q5 — Which port, opened on the attacker's machine, was targeted by the malicious web shell for establishing unauthorized outbound communication?

**What I did:** To find the attacker's listening port, I analyzed the PHP script content extracted via Follow TCP Stream.
**What I found:** Reading the script clearly showed the attacker's IP address and the target port for the outbound connection.
**Answer:** 8080

---

### Q6 — Recognizing the significance of compromised data helps prioritize incident response actions. Which file was the attacker attempting to exfiltrate?

**What I did:** To identify the targeted file, I filtered HTTP requests where the source is the victim's server IP, which represents traffic generated by the web shell.
**What I found:** The filtering showed an HTTP request containing the specific system file the attacker tried to exfiltrate.
**Answer:** /etc/passwd

## What I Learned
- **Input Validation:** Upload fields must strictly validate file types and extensions on the server side to prevent double-extension bypasses.
- **Reverse Shell Logic:** Attackers need to ensure their listener infrastructure (C2) is correctly configured to handle incoming HTTP methods.

- **Wireshark Proficiency:** Using specific filters like `http.request.uri` significantly speeds up the investigation.
- **Egress Filtering:** A firewall rule limiting outbound traffic or monitoring large HTTP responses can help prevent the exfiltration of sensitive files like `/etc/passwd`.
